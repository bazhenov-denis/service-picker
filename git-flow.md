<h3>Описание веток</h3>

<ul>
<li>main - здесь только стабильные версии приложения (для демо), каждый коммит имеет свой тег.</li>
<li>develop - основная ветка разработки, в нее собираются все фичи.</li>
<li>feature - ветки для фич. У каждой фичи должна быть своя ветка.</li>
</ul>

<h3>Порядок работы над фичами</h3>

<ol>
<li>От develop бранчим новую ветку, название должно иметь вид

> back/front-номер описание 

Например,

> back-1 add ServiceController

</li>
<li>Работаем над фичей, не забываем про тесты. Все коммиты льем в созданную ветку. Требования к именам коммитов:
<ul>
<li>краткое, но емкое отражение сути изменений;</li>
<li>стараемся уложиться в 50 символов;</li>
<li>используем английский;</li>
<li>первая буква - заглавная;</li>
<li>без лишней пунктуации;</li>
<li>глаголы только в инфинитиве.</li>
</ul>
Например,

> Add ui-bootstrap.js dependency

</li>
<li>Когда фича готова - делаем Merge request в develop, указываем ревьюера, ждем аппрув. При необходимости исправляем ошибки. **ОБЯЗАТЕЛЬНО** прочтите ниже как делать Merge request.
</li>
<li>Для коммитов в мейн: первая цифра тега - номер прошедшего демо, вторая - номер стабильной сборки. Например, v0.2 - вторая стабильная сборка перед первым демо.</li>
</ol>

<h3>Как сделать Merge Request</h3>
<p>В меню слева Code -> Compare revisions. В source указать ветку с фичей, в target - develop. **ВАЖНО:** обязательно выбрать Mark as draft и убрать галочку с Delete branch after merge. </p>
